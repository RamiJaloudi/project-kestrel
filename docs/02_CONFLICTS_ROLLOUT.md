# 02 — Conflicts, decisions, rollout

| Conflict | Decision, and whose |
|---|---|
| Partner wants bank red flags immediately vs no unreviewed client disclosure | Partner + supervising counsel: provide **reviewed, bank-approved commercial summary only**; queue candidates behind review gate |
| Immediate externally shared platform vs security review 4–6 weeks | Firm IT/security + partner: day one use approved existing platforms; external app later only after formal approval |
| Shared workspace vs restricted competitive pricing, privilege and walls | Clean-team counsel + conflicts team: centralized default-deny authorization; no unrestricted shared corpus |
| Board five weeks vs VDR data arrives six weeks | GC + partner: interim priority contract register, clear coverage and open-items statement |
| Generic taxonomy vs German software license nuance | Knowledge lawyer + German counsel: approved jurisdiction/type playbooks and versioning before broad use |
| AI scale vs source-citation accuracy | Senior associate + AI QA: explicit evidence/page validation, failure queue, attorney correction, quality evaluation |
| Halden requests deletion vs Freshfields long-term retention | GC/records/privacy: segregate client collaboration copies, matter record policy and legal hold; no blanket deletion promise |
| Cost and speed vs 400k pages / OCR / LLM | Architecture/security/partner: workload prioritization, incremental hashes, OCR-only scans, caching, token budgets and cost gates |
| Root Admin convenience vs legally approved playbooks | Root Admin manages technical data only; SME independently approves, person may not self-approve |
| Playbook update vs prior lawyer approvals/releases | immutable impact snapshot, SME rerun authorization, old finding history, correction workflow for released conclusions |
| Sensitive audit transparency vs inadvertent data leaks | Minimal scoped audit metadata, restricted incident logs and confidentiality controls |

## Scenario-relative rollout (production proposal, not candidate coding deadlines)
- **Week 0–1:** Confirm VDR rights, taxonomy/clean roster, use approved internal review and approved collaboration mechanisms. Prioritize material customer contracts + change-of-control. Track review coverage. No new external portal login.
- **Week 2–5:** OCR/citations/AI pipelines under firm governance; report sections from verified findings; interim board pack with scope gaps; security review proceeds.
- **Week 6–10:** Pending approved security onboarding, authenticated client/bank collaboration, restricted Q&A, audited releases, signing freeze.
- **After signing/closing:** snapshots, records retention, delete eligible collaboration copies after instructions/holds.

## Candidate build order (this ZIP)
S0 verify docs and base tests; S1 real auth + policy; S2 versioned ingestion/evidence; S3 playbooks and reviewer gate; S4 portal release + clean-team; S5 comparison/impact/notifications/SME rerun; S6 batch AI + RAG/report/regulatory; S7 hardening/public demo and presentation. Scope locks first submission to an end-to-end narrow vertical slice, not production completeness.
