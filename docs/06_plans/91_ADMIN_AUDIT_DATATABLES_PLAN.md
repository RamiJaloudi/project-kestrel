## Smallest useful delivery order

1. Add a selection-free wrapper mode and typed fixed transport contracts, then the **account directory grid** with Open account action. Keep the two-field editor and optimistic PATCH unchanged in purpose. Fetch a fresh exact account detail/revision before editing (new read route is justified; none exists now), and withhold the form on denial/stale detail. Default columns: display name, UPN, employer, employee ID, active, roles, Open; account ID/revision are secondary/detail fields. No export, saved views or bulk account changes in this increment.
2. Add the **audit grid**, retaining explicit Apply filters and the existing audit ZIP export controls. Default columns: UTC time, action, outcome, category, matter and object. Actor ID, clean-team scope, correlation ID and event ID can be optional columns; resolve human labels only through separately authorized projections. No guessed actor names or clickable arbitrary object URLs. Start with one applied category/time/matter descriptor; counts, grid and export must use that same descriptor.
3. Convert the **matter assignment and decision-history projections** after the first two are stable. Keep the access/wall forms and independent approval routes outside the grid. Use explicit Open target / Inspect decision actions; no row selection, bulk assignment, reprioritization or wall changes without a separately approved command contract.

The current [shared wrapper](../../frontend/src/KestrelDataTable.tsx) supports inventory, financial, tasks and findings, while saved views remain inventory/financial only. The new findings frontend is built, not yet a claim that every table is converted. Contract inventory, secondary registers and evidence tables remain separate rollout decisions. Literal reader tables must retain source order and coordinates.

## Narrow shared-wrapper changes

- Make selection a capability, preferably explicit `none | export | bulk`; update current consumers intentionally. `none` removes checkboxes, selected-count/actions and selected export state. Compute default order and saved-query column indices from named columns and the actual selection-column offset. Do not carry the hardcoded index `1` into a table without Select.
- Separate a typed scope descriptor from mandatory source `matter`. Directory authority can be global Root configuration; audit matter is optional. Choose transport from a static application-owned mapping, never from URL/user-supplied arbitrary endpoints. Keep query fields, sortable/searchable columns and category/organization/active filters allowlisted. No generic SQL-column input.
- Reuse abortable request generations, safe non-JSON status handling, escaped React cells, 15-second pending-request protection and parent `onDenied`. Remount/clear on authenticated identity, scope or applied-filter change. Background validation may clear a stale editor but must not overwrite a dirty draft with new account values.
- Keep audit-specific package export outside generic `allowExport`. An abort/epoch-checked fetch should suppress stale downloads after filter/session/scope change; preserve fresh server reauthorization after rendering. Initially expose no generic selected CSV/XLSX, share or saved-view controls for either dataset.

## Server paging and fresh authority

Do not call the existing legal source-table `begin()` guard for Root account configuration: it delegates to legal matter access and denies a Root-only account. Reuse authentication/input-stamp techniques with **directory Root**, **registry administration** or **audit-category** authority as appropriate. Reauthenticate after preparing each read; a removed role, expired assignment/named grant, new wall or changed session must withhold rows/counts/detail. Successful writes require a fresh appropriate post-write receipt check without treating their own expected mutation as an unrelated stale-input error.

For directory rows, authorization precedes count/filter/page, stable ordering ends in account ID, and every filter/sort is typed. For audit, reuse the same retained-object checks as `selected()` **before** counts or paging. SQL LIMIT/OFFSET over an unauthorized superset followed by row filtering yields incorrect totals and can leak structure. The current selector streams candidates and caps permitted results; it is not a scalable exact-count pager. A first bounded audit-window implementation may retain the 1,000 permitted-event ceiling and return 413 on a larger authorized window, then page only that proven set. State that limit explicitly; do not report truncated totals or production-scale performance. Broader indexed/cursor paging needs measured design and its own review, not a silent migration.

## UX, retention and acceptance

Current code findings to close: account refresh failures retain old directory/form state and have no abort/response generation; audit matter-input edits do not clear prior rows, failed loads retain them, and late loads can replace a newer scope. Clear protected rows/details on denial and applied-scope change. Label draft inputs versus applied filters, distinguish loading/error/empty, use readable UTC timestamps, and retain IDs/employee numbers as strings. Preview fixtures must make no authenticated directory/audit requests.

Table filtering/export adds no retention policy. Keep audit/decision history and signing records under existing retention/hold controls; do not add delete/purge actions, browser persistence, localStorage snapshots or claims of WORM storage. A ZIP manifest proves file integrity, not immutable hosting. Account metadata changes remain separately audited; query refresh must not mutate task/legal state.

Acceptance should cover Root-only directory success versus lawyer/SME/external denials; no secret-field serialization; employee-ID leading zeros/duplicate employer constraint; stale account revision; mid-render Root removal; assigned/walled registry negatives; own audit versus explicit auditor grants; expired named clean-team grants; retained-union restrictions; identical authorized count/page/export sets; forbidden sort/filter keys; 1,001-event refusal; time-window validation; CSV/HTML safety; and session/filter change during slow query/export. Preserve [profile tests](../../backend/tests/test_profile.py), [audit governance tests](../../backend/tests/test_observability_governance.py) and [audit render/window tests](../../backend/tests/test_qa_ai_archives.py). Browser checks include keyboard action cells, narrow/zoomed layouts, late-response suppression and an unsaved name edit surviving background validation.

The findings/source-profile integration is a separate security-sensitive change: the frontend now supports a minimal sanitized source-profile contract that withholds prior analysis/review metadata while distinguishing new review defaults and new manual-finding authority. Board unavailable metrics remain nullable. Full-source-chain uncertainty can still withhold the whole-document panel. This is not proof that every prior workflow is preserved; backend regression and signed-in browser checks remain required.
