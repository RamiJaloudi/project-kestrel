## Original plan

24 November 2026. Planned next after scoped-audit acceptance. Convert only the Registry page's two native tables; the broader rollout and final Excel/manual acceptance remain separate. No implementation or test pass is claimed by this plan.

Use two server-paged, selection-free datasets: `registry_access` and `registry_history`, with a required matter ID and fixed validation-API transports. Strict draw/start/length (maximum 50), allowlisted sort/direction/literal search and column filters; reject source/account/audit/saved-view/export/selection fields. Return permitted totals and current administration revision as a display/staleness hint. A refreshed grid must never silently replace the expected revision of a dirty decision form.

Access rows represent accounts with any historical assignment or direct-wall record, including expired/revoked participants. Preserve that set; it is neither the entire directory nor only active members. Use the account ID as the stable row key, with UPN, employer, active assignment, direct legacy wall and effective wall shown distinctly. Effective walls include current published/client/person rules and cannot be written back as the direct-wall flag. Evaluate active assignments and effective walls against one request clock. History rows use the existing AdministrationDecision ID, not row index; include only the current `matter.%`/`access.%` decision families with revision, kind, rationale and UTC time. Actor/target IDs may be optional columns. Escape metadata in React and provide no arbitrary source links.

Authority is current firm Root plus `administration.require_matter()`: an active direct management assignment and no applicable wall. Pending/rejected matters remain administrable. The legal-source `begin()` guard or Principal's validated-only matters would incorrectly exclude pending matters and must not be reused. Authenticate and verify current administration scope before counts and again after preparing output. Original access/history reads must retain the same boundary and receive fresh guards where required. Root still has no source override or self-access command.

Preserve client creation, leading-zero client/matter numbers, new pending matters, validation decisions and assignment term/rationale/CAS behavior. Keep the free-UPN path for first assignments: a grid of historical participants cannot be the only account selector. If Open target is added, obtain fresh matter/target context first. The existing editable direct-wall checkbox is misleading because direct changes are already rejected; replace it with a read-only direct-wall state and a link to the independently approved Conflicts workflow. An assignment save must preserve existing wall records and cannot treat an effective restriction as a grant or declassification.

Key the matter workspace by authenticated identity and selected matter; abort and suppress stale responses when scope changes. Clear private form state atomically if either grid is denied. Disable matter switching and duplicate submissions during writes. Background table polling preserves dirty text and its pinned administration revision; accepted commands require fresh context before another command. Unknown write outcomes require read-only context/history inspection, never automatic resend. Preview remains static with no authenticated requests.

Ownership to assign before coding: backend registry schema/service/API/tests; frontend Administration refactor plus two registry grid components; root shared typed transports/selection-free integration, launch notices and live/browser acceptance. Scope requires no model, migration, bulk assignment, direct wall change, legal approval or public service.

Tests first: Root administration of pending matters; ordinary lawyer/SME/external denial; unassigned/expired/walled Root denial before counts; expired participant projection; direct/effective wall distinction; stable history IDs/order; strict request/field rejection; current role/assignment/wall/session changes during preparation; optimistic revisions and no writes after permission loss; immutable existing wall records through assignment updates; original registry/numbering/Conflicts tests. Browser checks cover paging/search, switching matters with slow responses, dirty revision preservation, expected read-only wall behavior, narrow/keyboard use and no accidental command from a grid action.

Rollback restores only changed code and preserves all registry decisions, assignments, walls, source records and previous DataTables access fixes. DataTables selection is not authority; these grids expose no selection, saved configuration or generic export.
