# Scoped audit DataTable and matching exports

24 November 2026. Planned next increment after account-directory acceptance. This is a plan, not an implemented or verified audit-grid claim. Resources Excel/manual acceptance remains the final gate.

Replace AuditWorkspace's native list with a server-paged, selection-free DataTable. Keep the existing ten audit metadata fields and category/own-versus-explicit-auditor/named-clean-team/retained-source restrictions from `auditing.selected()`. Never infer actor names, make arbitrary object links or provide Root source access. Preserve all records, existing export formats and the explicit statement that integrity manifests are not WORM storage.

Add strict POST `/api/v1/audit/query` with common draw/start/length (at most 50)/allowlisted sort/direction/literal global and column search, plus `audit_filters:{category,matter_id?,from_time?,to_time?}`. Reuse one permitted-selection pipeline for totals, search, order, paging and export. Retain the existing **1,000 permitted-event baseline-window ceiling before search**. Larger windows return 413 and require narrower matter/time filters; do not truncate counts or make scale claims.

POST `/api/v1/audit/export-query` accepts the same query plus one of JSONL/CSV/HTML/PDF. It exports **all filtered rows in the applied audit window, independent of page offset/size**. The ZIP manifest records scope, search, column filters, order, event IDs/count, exporting identity and file hash. Reauthenticate and repeat the complete unpaged selection after preparation/rendering; changed permissions/content/session must withhold output. The old GET routes remain compatible and receive fresh read guards where necessary. Do not create a query audit event inside its own compared selection.

Frontend draft category/matter/local-time inputs are distinct from an immutable applied descriptor. Editing any scope input clears the old grid and disables export until Apply and a successful draw. Use explicit UTC conversions and reject invalid/reversed times. The shared wrapper gets an application-owned `audit` transport, no global matter requirement, no selection/generic export/saved configuration, and a typed `onAuditQuery` callback: null while pending/error/denied, exact full query after a successful draw. Parent ZIP downloads use that successful query, CSRF, no-store, MIME validation, abort and scope/epoch checks before creating a download. Search/column/order/scope changes invalidate pending exports. Pause the periodic refresh during export rendering so an unchanged timer does not cancel it; explicit query/scope changes still cancel. Server checks remain mandatory.

Ownership: backend agent owns new audit-table schemas/service/tests and auditing API integration; frontend agent owns AuditWorkspace plus its two Administration/PortalApp call sites; root owns shared-wrapper audit types/transport/pause flag, integration, launch notices, live/browser verification and this record. Preview and anonymous routes must make no audit requests. Existing source/account DataTables payloads and capabilities stay unchanged.
