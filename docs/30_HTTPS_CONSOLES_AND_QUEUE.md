## Implemented and verified

- Start opens HTTPS Portal Home only, pgAdmin and the interactive SQL operator console. It launches five titled component consoles: API/portals/Swagger 8443; HTTP redirector 8000; PostgreSQL database/queue status; synthetic-analysis worker; service health monitor. They expose timestamp, uptime, health, completed/failed counts and last activity every ten seconds. Queue/monitor counts refer to jobs/probes; PostgreSQL queue totals contain no matter/document identifiers. The hidden owner only controls the process tree and is not another API.
- GET/HEAD HTTP links redirect with 308 to the same allowlisted host/path/query on HTTPS. HTTP state-changing requests are rejected rather than forwarding credentials. All generated portal/preview/API links use HTTPS. Host-bound sessions and CSRF checks remain enforced.
- The project CA is in CurrentUser Root, not LocalMachine. Its private key and leaf key have owner ACLs in ignored .runtime. Leaf certificate covers localhost, the four portal aliases and 127.0.0.1, lasts 90 days and renews near expiry. CA rotation is an explicit operation. On a new Windows account, the first installation can require a native Windows trust confirmation. Trust is local development only; do not distribute CA private keys or reuse them for Azure. Stop does not remove trust. The exact installed public certificate was compared with the current-user store; Windows HTTPS validation returned 200 without disabling checks.
- Safe request summaries contain route templates and correlation IDs, never query strings, document IDs/passages, submitted credentials, exception messages or locals. Pulses and diagnostic events append to component JSONL files. Each launch/build/supervisor gets retained run logs. Current status JSON files are replaceable snapshots; retained evidence is in logs. No automatic log deletion is configured. Existing scoped clean-team/SME/administrative audit export boundaries remain unchanged.
- Migration 0005 adds retained synthetic jobs. Scoped Legal SME enqueue binds an idempotency key, rationale and exact published playbook hash. Independent legal publication is required. Only embedded examples run; no external provider or source-document ingestion occurs. PostgreSQL workers use SKIP LOCKED, lease fencing and a maximum of two attempts. Execution exceptions retry after ten seconds; permission failures terminate denied; expired crash leases require an explicit scoped recovery. Failed processes never restart automatically. Successful/denied jobs cannot be edited or deleted through normal DB operations; these guards are not WORM against the database owner.
- Playbook Management and Administration's policy area expose queue authorization/status/result inspection and grouped Jobs Swagger. Results contain original example offsets and literal evidence, marked candidate_only. Publication never enqueues work. Historical impact snapshots, SME task inbox, historical reruns, live AI, OCR, immutable storage and report generation remain separate phases.
