## Concrete XLSX hidden-content acceptance gap

[SOURCE FINDING, NOT A NEWLY EXECUTED EXPLOIT] `adapters/extraction.py` calls `workbook(..., extended=False)` for XLSX and `extended=True` for XLSM. `spreadsheet_source.py` records hidden rows/columns, comments/defined names, worksheet manifest and `hidden_content` only in the extended path. The XLSX baseline retains sheet state but not those equivalent row/column/opaque metadata markers.

`adapters/disclosure.py::sanitize` excludes hidden/very-hidden XLSX **sheets** and units already marked hidden_content. It does not independently exclude a hidden row or column on an otherwise visible historical XLSX sheet. Therefore blanket “all hidden XLSX content is detected/protectively handled/removed from the flattened transcript” acceptance is unsupported: such row/column text can be carried into a transcript unless the human explicitly removes it. A new PDF container alone does not prove the input text selection was safe.

Bounded next action: parity metadata for new XLSX extraction, protective intake and explicit hidden/opaque source handling, plus safe exclusion or fail-closed reconstruction for already-retained XLSX. Preserve old bytes, extraction JSON/hashes, classifications, approvals and signed history. Add adversarial visible-sheet hidden-row/column/name/comment tests and verify prospective intake, old-source disclosure and external release boundaries. Root authorized this next security slice after this audit; **it was not yet implemented or tested when this file was saved**. Do not describe the gap as fixed without subsequent evidence.
