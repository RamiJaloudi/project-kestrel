# Remembered sign-in and saved usernames

[USER DECISION] Allow saved usernames/passwords and cookie-based persistence throughout the application.

[DESIGN] Shared login form supports browser password-manager saving/autofill and an opt-in thirty-day remembered sign-in. Store only an opaque session token and a username preference in Secure, HttpOnly, SameSite=Strict, host-only cookies with Path=/. Passwords remain outside app cookies/storage. A normal sign-in uses a browser-session cookie with a thirty-minute server expiry. Remembered sign-ins have a fixed thirty-day lifetime; page restoration does not extend it. Sign-out revokes the server session. A separate control forgets the username.

Scope: backend auth service/API, common portal login form and Swagger CSRF restoration; no DB schema change. Restore page CSRF from an authenticated cookie only after an exact HTTPS Origin check; stable session-bound CSRF avoids invalidating other open tabs. Other state-changing routes keep their existing Origin/CSRF checks. Account, organization, roles, matter, walls and clean-team checks still run against current database state. No shared wildcard-domain login.

Acceptance: cookie flags, expiry alignment, no password/username authority in session cookies, strict remember flag validation, fresh-page restoration, simultaneous-page CSRF stability, legacy-session restoration, cross-origin/host denial, sign-out and live revocation. Build frontend; run auth tests on SQLite and native PostgreSQL, then live HTTPS checks on all four portals. Update Start/Stop guidance and restart owned services, preserving accounts, CSV exports, logs and data. Rollback restores the prior auth/form code; existing saved tokens can be revoked normally without data deletion.

## Implemented and verified

All four portal shells share the Remember username and stay signed in (30 days) control. Username preference is a separately URL-encoded, HttpOnly host cookie; only the same-origin preference API supplies it back to the form. Forget saved username clears that preference. Sign-out always revokes the current server session and clears its cookie, while retaining the username until explicitly forgotten. Unchecked sign-in clears an older username preference and creates a browser-session cookie with a thirty-minute server expiry.

The login form has named username/current-password fields, autocomplete enabled, and reads submitted FormData so a password manager can fill fields without React change events. Password saving/autofill is controlled by the browser's password manager and its settings; the application does not store the raw password in any cookie, localStorage or sessionStorage, and cannot force a browser save prompt. Check Remember once on each relevant portal for persistent sign-in. Sessions stay host-bound and do not authorize a different organization.

POST /api/v1/auth/session requires an authenticated host-bound session cookie plus exact HTTPS Origin, and restores identity and a session-bound CSRF value. For legacy sessions it updates the older random CSRF hash once. Reopening pages does not extend expiry; concurrent restored pages share the same session CSRF. Other state-changing APIs retain normal CSRF checks. Swagger's same-origin request interceptor restores the current CSRF before protected mutations, reusing remembered portal login. Cross-origin interceptor targets are rejected. Browser credential/API-token persistence in Swagger storage remains disabled.

Validation: full backend suite **104 passed, 1 PostgreSQL-only skipped, 1 known dependency warning**. All **6 remembered-sign-in tests passed on PostgreSQL** in isolated schemas. Frontend TypeScript/Vite build passed. Actual HTTPS smoke passed on Administration/Firm/Halden/Castlegate: persistent cookie attributes, fresh-client restoration, stable CSRF, sign-out revocation, retained username and explicit forgetting. Swagger interceptor checks passed for restoration, GET/login exclusions and cross-origin protection. Root Stop/Start succeeded with account/data/log/export retention. Desktop tool returned access denied, so browser visual/password-manager prompt behavior was not inspected; no visual verification claim is made.
