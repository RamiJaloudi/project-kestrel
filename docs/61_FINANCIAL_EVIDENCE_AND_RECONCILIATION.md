# Financial evidence and reconciliation

[DEMO] 24 November 2026. This increment supplies a human-capture baseline, not a general financial extraction engine. Migration 0033 adds five retained tables: facts, decisions, matter bank gates, reconciliation cases and independent resolutions. No live approvals or financial data are seeded by migration.

## Workflow

1. In Firm > Documents ingest `fixtures/wave2/financial-evidence-synthetic.txt` into the validated synthetic matter. Confirm its handling through the normal authorized workflow.
2. Open Financial Evidence. Expand Capture a financial fact and select the document and exact numeric token. Enter literal entity, metric, period label, currency code, scale label, accounting basis and consolidation scope. Declare period dates and decimal convention explicitly. Every literal dimension must occur in the selected original-language context or separately selected header spans; a reviewer must check its interpretation.
3. A different source-cleared lawyer verifies or rejects the immutable fact. Amounts use exact Decimal arithmetic and PostgreSQL NUMERIC(38,12); SQLite tests store exact decimal strings. Binary floats, ambiguous grouping, NaN and out-of-range values are rejected; scientific notation requires an explicit selection. Scale is explicitly ×1, ×1,000 or ×1,000,000. No FX or unit assumptions.
4. Query by typed dimensions and amount ranges. Ranges require a currency. Counts are computed after individual authorization. Compare two verified facts with matching entity, metric, period, currency, accounting and consolidation scope. Scale is normalized before comparison. Conflicting comparisons create one deduplicated retained case, even when the comparison order is reversed. A different source-cleared SME may prefer either source or retain the conflict unresolved with rationale; neither fact is overwritten.
5. Original-source facts remain internal. To publish financial facts externally, first build and independently release a sanitized disclosure through its separate workflow. Capture facts against that transcript, obtain independent numeric verification, then independent SME fact release. Internal reconciliation assessments are not automatically published with their inputs; external users may only compute deterministic comparisons from their own released facts. Castlegate also requires Administration > Financial access to be enabled for the matter. This default-off feature gate never grants content access. Each row, citation and comparison still requires current audience release, wall/PDP clearance, unexpired derivative and active approver authority.
6. Questions > Financial / structured accepts exact filters and returns verified facts with evidence. Automatic selects financial SQL only when explicit typed financial filters are supplied via the API; otherwise it uses BM25. It never guesses dimensions from free text or asks a model to calculate amounts. Cached financial answers recheck all contributing facts before returning counts or citations.

## Integrity, operation and rollback

Fact proposals, decisions, reconciliation and configuration revisions are append-only, backed by database triggers. Source snapshots bind evidence to current policy. New source attributes, revoked access or revoked releases deny future financial views and cached answers. Signing includes the new records and blocks new facts, resolution and access expansion; append-only revocation and feature disabling remain possible. External financial outputs contain derivative evidence and no original source IDs, private reviewer identities or staff productivity metrics. Downloads already held by a recipient cannot be recalled.

Swagger: `/docs/financial`, within the existing shared HTTPS API. The existing Start/Stop batch files remain the entry points; no duplicate financial server is started. The bank gate defaults off and startup does not enable it. Populated migration downgrade is deliberately blocked; rollback keeps retained evidence and uses verified backup/rehearsal procedures rather than deleting rows.

Migration rehearsal/application preserved all 110 prior application-table digests and 17 source versions / 16 logical documents / 17 version links. The encrypted backup was restore-verified. Receipts: `.runtime/prompt-audit/financial-migration-*`. Focused financial/migration/signing checks: 12 passed. Focused financial/retrieval checks including typed Q&A: 14 passed. PostgreSQL workflow/Decimal checks: 7 passed before the added typed-Q&A case. Frontend TypeScript/Vite build passed. The financial baseline full regression passed 278 tests with 1 skipped; final typed-Q&A integration passed 25 focused tests and 8 PostgreSQL checks. Spreadsheet refinements are tracked in docs/62_LITERAL_SPREADSHEET_EVIDENCE.md and a new full regression. No paid AI calls were needed.
